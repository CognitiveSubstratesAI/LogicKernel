# LogicKernel v0.1.0-pre.1

A pre-release of LogicKernel, a standalone logic-programming kernel for Julia. LogicKernel is a port
of [SWI-Prolog](https://www.swi-prolog.org)'s kernel (swipl-devel): upstream's C and Prolog sources
translated file by file, at upstream's paths and under upstream's names, and checked against a live
`swipl`. What is ported so far, upstream file by upstream file and function by function, is listed in
`docs/port_inventory.md`; how it is built is in `docs/architecture.md`.

This tag marks a state in which the engine's answers are checked against SWI-Prolog's for everything that
is ported; the list below is every place where they are known to differ, or where a feature is
missing, grouped by when it is scheduled to change.
The host-facing Julia API is `PL_global_data{T}()`, `PL_local_data{T}(gd)`, `load_file!` and
`query_answers`. `query_answers(ld, goal; limit)` is STABLE from v0.1.0-pre.1: its signature, its
return shape (a vector of answers, each the goal with that solution's bindings substituted) and
`PrologException` (an uncaught Prolog exception, its ball as a term) will not change; a goal may be
module-qualified (`M:G`, taken as SWI-Prolog's `PL_call` takes it); goals as text, bindings by name and
a lazy iterator will be added to it, not change it. It is exported
together with `PrologException` and `load_file!`; the README's example of the whole host path runs
as a test. The other entry points are the current ones: the loader is the minimal one and becomes
`consult` with the module system, the call stays.

## Known divergences from SWI-Prolog

### A. Scheduled for attributed variables (AV)

* There are no attributed variables: `put_attr/3`, `get_attr/3`, `del_attr/2`, `freeze/2`, `dif/2`,
  `when/2`, wakeup of delayed goals and `copy_term/3`'s attribute goals do not exist. (Phase AV.)
* `numbervars/4`'s `attvar(skip|bind|error)` option is accepted and validated, but has no effect: it is
  untested against a real attributed variable until they exist. (Phase AV; ported in AV5 — the line goes
  with the release that carries it. `attvar(bind)` on a module without a hook answers differently until R2's
  `'$attvar'` module, test_attvar_wakeup.jl nv04.)

### B. Scheduled for the module system and loader (R2)

* Only the modules `user` and `system` exist. `module/2`, goals qualified with another module,
  `Goal@Module`, module transparency and meta-predicate declarations are not supported; a clause or
  goal naming another module is refused with a named error. (Phase R2.)
* There is no library or file loading beyond one Julia call: `load_file!(gd, ld, path)` consults one
  file into `user`. `use_module/1,2`, `library(...)`, `ensure_loaded/1`, `include/1`,
  `initialization/1,2`, conditional compilation, DCG rules, `term_expansion/2,4` and
  `goal_expansion/2,4`, reconsulting a file and redefining a predicate another file defined are
  refused with a named error. Messages (warnings, singleton variables, syntax errors) are returned to
  the host instead of printed. (Phase R2.)
* `findall/3,4`, `bagof/3` and `setof/3` are stand-ins: the kernel compiles SWI-Prolog's own clauses
  from `boot/bags.pl` when the database is created, as `system` predicates, where SWI-Prolog keeps
  them in the module `'$bags'`. `findnsols/4,5` is missing. The same holds for `catch/3`, the
  `setup_call_cleanup` family, `call/1`, `length/2` and `numbervars/3`. (Phase R2, when `boot/*.pl`
  is loaded.)
* Errors raised inside those stand-in predicates carry `system:` as their module where SWI-Prolog's
  carry `'$bags':` (for example `context(system:findall_loop/4, _)`); and because the stand-ins are
  not meta-predicates, a non-callable cleanup goal is reported as `type_error(callable, Goal)` where
  SWI-Prolog reports `type_error(callable, user:Goal)`. (Phase R2.)

### C. Scheduled for the garbage collector (G1)

* There is no garbage collector for the stacks: global-stack cells are reclaimed only on
  backtracking, so a long deterministic run fills the stacks until `stack_limit` (default 1 GiB) and
  then raises `resource_error(stack)`. A host running many queries must discard each query's foreign
  frame, as embedding code does with libswipl. (Phase G1.)
* A thrown exception ball is kept on the global stack until the outermost query ends and is then
  released at once; SWI-Prolog keeps it for the thread's life and lets its collector free it.
  `nb_setval`/`b_setval` are not ported and would need this revisited. (Phase G1.)
* A term reference created before a foreign frame and written inside it with a float, a big integer or a
  string keeps that value after the frame is discarded or rewound; in SWI-Prolog the reference then
  dangles (undefined behaviour, the C caller's responsibility). The kernel keeps the read defined.
  (Revisit with G1.)

### D. Small, open

* `term_hash/2`, `variant_sha1/2` and `variant_hash/2` are not Prolog predicates; the Julia functions
  `pl_term_hash`, `pl_variant_sha1` and `pl_variant_hash` hash atoms and numbers differently from
  SWI-Prolog, so their values are not SWI-Prolog's (equal terms hash equally; variants digest
  equally). (Open: when the term interface can give a value's bytes, or when a library needs it.)
* There is no Prolog flag table: `set_prolog_flag/2`, `current_prolog_flag/2` and
  `create_prolog_flag/3` do not exist. The flags the kernel reads sit at SWI-Prolog's defaults, so
  `iso` and `prefer_rationals` cannot be set to `true`. (Open; the flag table comes with R2.)
* The arithmetic function `roundtoward/2` is not ported (78 of SWI-Prolog's 79 evaluable functions
  are): it raises `type_error(evaluable, roundtoward/2)` where SWI-Prolog evaluates it, and the
  kernel has only the to-nearest rounding mode. (Open.)
* Each term reference holds one global cell until backtracking; a void argument (`_`) passed on to a
  call is likewise a global cell where SWI-Prolog uses a local one, so a very long deterministic
  recursion that passes `_` meets the stack limit where SWI-Prolog does not. (Open: reclaimed by G1
  or by moving term references onto the local stack.)
* The stack limit is checked once per call, after the fact: the stacks can pass `stack_limit` by one
  built-in's or one clause's layout before the error is raised. The overshoot is bounded, not zero.
  (Open.)

### E. By design

* The numeric functions (`sin`, `exp`, `lgamma`, `**` and the others) call glibc's `libm.so.6`, as
  SWI-Prolog does, so they match SWI-Prolog bit for bit on Linux/glibc, can change with the glibc
  version, and are not supported on other systems.
* `random/1`, `random_float/0` and the other random sources use the kernel's own generator
  (SplitMix64), not SWI-Prolog's; the stream differs and cannot be seeded (`set_random/1` is not
  ported).
* The context of a stack-overflow error is the atom `stack_overflow`, where SWI-Prolog's is a dict
  tagged `stack_overflow`; the kernel has no dicts. The formal term, `resource_error(stack)`, is
  SWI-Prolog's.

## Fixed (was on main before this release)

* `:- dynamic X/0.` (a variable as the name of a zero-arity predicate indicator) raises
  `instantiation_error`, as SWI-Prolog does; it raised `type_error(atom, _)`. (bc4f22e)
* The global stack had no limit: only the local stack's overflow was raised, and nothing stopped
  terms from growing the global stack. Now one limit covers the local, global and trail stacks
  together, as SWI-Prolog's `stack_limit` (default 1 GiB), and exceeding it raises
  `resource_error(stack)`. (ed0d5cc, 76a20b4, ef58ea4)
* `2 ** (2 ** 64)` and the other integer results too big to build raised a "not ported" error; they
  raise `resource_error(stack)`, as SWI-Prolog does. (ed0d5cc, 6d58aa7)

## Caught before release

Found by the gates and fixed before they reached `main`:

* While the stack limit was being built, it was for a time checked on the global stack alone and
  missed a last call (frame reuse); both were fixed before the limit landed.
* On Julia 1.13.2, converting an integer beyond the range of a double (`float(10**400)`, `/` on such
  integers, comparing them with floats) returned the largest finite double instead of raising
  `evaluation_error(float_overflow)`, because 1.13.2 changed how `BigInt` rounds to `Float64`; the
  kernel now decides the overflow itself. (3bec9d1)
* `erfc/1` follows SWI-Prolog's own definition at the pinned commit (`1.0 - erf(x)`), not the C
  library's `erfc`; the results differed in the last digits. (a1b5662)

## How this release was checked

* **The oracle.** Every answer is compared with a live `swipl`: SWI-Prolog 10.1.18, built from
  swipl-devel commit 8609e216cab90e476dafac799a9e323151e3c499 (`tools/SWIPL_VERSION`). Every gate
  asserts the version and the commit where it runs, so the ported source and the oracle cannot drift
  apart; CI builds the same commit. The CI runners are pinned to `ubuntu-24.04`, because the numeric
  functions call the system libm and the oracle is built on the runner.
* **The gates.** The full test suite runs in CI's Evidence workflow on all three term
  implementations (the reference type and two alternatives), with the swipl differentials live; the
  static analysis (JET, Aqua, AllocCheck) runs in CI and before each push; the live swipl
  differential runs on every push to `main`. A change lands on `main` only by fast-forward to a
  commit whose full CI run is green.
* **A benchmark against the previous milestone.** Four classic programs (nreverse, qsort, derive,
  poly_10), each first checked to give SWI-Prolog's answer, timed 30 times per side on a quiet
  machine and normalised by SWI-Prolog's own time in the same process: none is slower than at the
  previous milestone; derive and poly_10 are faster (poly_10 from 30× to about 4× SWI-Prolog's
  time, its allocations per call from ~100,000 to 0).
* **Mutation testing.** Each ported step has a battery of deliberate faults (mutants) that its tests
  must catch. The 29 batteries were re-run, 487 mutants, after the mutation drivers were fixed: a
  mutant that no longer loads, or a test run that fails with no failing test, was previously counted
  as caught and is now counted as no verdict. The re-run left 33 survivors, each classified before
  anything was changed: 6 whose batteries were aimed at test files the tests had since moved out of
  (re-aimed: caught by the existing tests), 8 tests too weak to see the fault (strengthened: each fault is now
  caught by its new test), 13 in code reached only by the term-layout work's own white-box tests or
  by nothing (shown by a call probe over the whole suite) — 12 of them are uncaught by the whole
  suite, and that code is on the list the last L1 stage deletes, 2 equivalent changes, and 4 that the CI lane could not judge (its analysis
  tools were missing; fixed, and the faults are caught). The re-run also found one real port defect,
  the `:- dynamic X/0.` error above, three tests that could never fail (fixed), and a CI job that
  skipped its static analysis silently when the tools were missing (now an error, and every run
  records that the analysis ran).
