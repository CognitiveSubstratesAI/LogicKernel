# Upstream defects found by porting (swipl-devel)

Porting swipl-devel line by line, and checking each port against a live `swipl`, finds defects in
upstream itself. This file lists them. Each one is:

- recorded **internally first**, as a LogicKernel issue with its reproducer;
- **reported upstream later, by hand** (user, 2026-10-03). The org token cannot open issues
  outside CognitiveSubstratesAI.

An entry closes when its upstream report is filed and linked here.

How each was found:

- **#1:** a live differential of index layouts against swipl (`test/db/test_index_swipl.jl`).
- **#2:** reading `pl-termhash.c` while porting it, then measured on swipl.
- **#3:** the live `=/2` differential (`test/core_lang/test_unify_swipl.jl`).
- **#4:** porting `pl-supervisor.c` with `arg1Key` (V4a), then probed on swipl with the two facts.
- **#5:** porting `classify_exception_p` (V5b), against the comment on its enum; then the live
  `'$urgent_exception'/3` differential and a real stack overflow probed on swipl.
- **#6, #7:** the research for the head-unification chunk (2026-10-06): reading `analyseVariables2`, `mark_bvar_access` and `decompile` while mapping `optimise_unify`, then probed on swipl (the workspace's `docs/research/v9-inline-unification/`).
- **#8, #9:** R1c's live differentials (`test/core_lang/test_read_swipl.jl`): raw syntax errors against `term_to_atom/2`, and `atom_number/2` on every number syntax; then read in pl-read.c and pl-prims.c (2026-10-07).
- **#10:** R1d's live differential (`test/core_text/test_read_term_swipl.jl`): an unclosed Unicode quote against `term_to_atom/2`; then read in pl-read.c, and checked against UTF-8 locales at a reviewer's request (2026-10-07).
- **#11, #12:** R1e's live differential (`test/core_text/test_write_swipl.jl`): `dynamic é` and `'[]'(a)` in the hand corpus, `quote_non_ascii(true)` in its flag sets; then read in pl-write.c (2026-10-07).

When one is fixed upstream, the LogicKernel side changes as follows:

- **#1:** the divergence ends, so drop `# DIVERGES` and the check that pins swipl's behaviour.
- **#2:** port the fix and flip the pin.
- **#3:** go back to one swipl process per mode.
- **#4:** drop the `# DIVERGES` in `arg1Key` (the code stays as it is), and add the two facts to a
  live swipl differential.
- **#5:** port the fix (the class test on `resource_error(_)`) and flip the class pin; the live
  differential then checks the fix.
- **#6:** port the fix in the variable analysis; a variable goal then stops the move as other goals do.
- **#7:** port the decompiler's fix with V9's decompiler.
- **#8:** drop `clearBuffer`'s `# DIVERGES` if the fix leaves the text empty, else follow it; flip the pin.
- **#9:** drop `pl_atom_number2_va`'s `# DIVERGES` and port the fix; the pin then checks it.
- **#10:** port the fix (both callers UTF-8, `makeErrorTerm` with `PL_UTF8_CHARS`); the differential then checks it.
- **#11:** drop `_signed_char` where the fix makes the character unsigned (and test the first character in `atomType` if it does); the differential then checks it. The kernel follows swipl ON X86-64: a swipl oracle on an unsigned-`char` platform (Linux aarch64) disagrees with it there — that is the platform, not a regression.
- **#12:** port the fix (`bracketPairAtom` above ASCII only); the differential then checks it.

**#4 and #5 are both fixed upstream** (`97370c0e`, `85d0cc2`, 2026-10-06), after the pinned
`bae881a2`. They move at the SAME swipl pin bump, and in ONE commit the kernel code and the oracle
move together:
1. the kernel takes `97370c0e` (drop `arg1Key`'s `# DIVERGES`, port SWI's new `first_arg` test from
   `tests/rational/test_rational.pl`) and `85d0cc2` (`classify_exception_p` as fixed, the class pin
   flipped);
2. the oracle moves to a swipl build that contains both commits — the local build and CI's
   container.

If only one side moves, the 14-ball `'$urgent_exception'/3` differential fails: correctly, but
confusingly.
